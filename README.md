# TOYOCHO ALERT

東京メトロの列車が駅に近づいたら、音とお知らせで教えるアプリ。

いま **Ver1（旧版）と Ver2（新版）が同じフォルダーに並んでいます**。
Ver2の動作を確認したうえで、Ver1を消してください（消し方は最後の章）。

---

## Ver2（新版）の起動

```
.venv\Scripts\python.exe -m uvicorn toyocho.api:app --port 8100
```

ブラウザで `http://localhost:8100` を開く。
スマホで使う場合は、同じWi-Fiにつないで `http://（パソコンのIPアドレス）:8100` を開き、
ブラウザのメニューから「ホーム画面に追加」する。

### できること

- 東京メトロ**全10系統**（9路線＋丸ノ内線支線）に対応
- 駅・方面・行先を選んで見張りを登録（複数登録できる）
- 列車が**近づいた時点**でお知らせ（到着を待たないぶん、通知が1駅ぶん早い）
- 複数の人が同時に使える（他人の見張りは見えない）
- 画面を開いていれば即時に音と振動、閉じていてもお知らせが届く（要・鍵の設定）

### お知らせ（Web Push）を有効にする

画面を閉じているときにも通知を出すには、鍵を用意して環境変数に入れる。

```
.venv\Scripts\python.exe -c "from py_vapid import Vapid01; v=Vapid01(); v.generate_keys(); print(v.private_key_bytes()); print(v.public_key_bytes())"
```

`VAPID_PRIVATE_KEY` と `VAPID_PUBLIC_KEY` に設定して起動する。
未設定でも、画面を開いている間の通知は動く。

> iPhoneでは、**ホーム画面に追加したあと**でないとお知らせを受け取れません（iOSの決まり）。

## 開発

```
.venv\Scripts\python.exe -m pytest            # 自動テスト（通信なし・約3秒）
.venv\Scripts\python.exe -m pytest -m live    # 本物の上流と駅名を突き合わせる
```

### 作りの考え方

```
toyocho/
├─ domain/     判定の中核。外部に一切依存しない（通信もDBも使わない）
│              → 通信・DBなしで全パターンをテストできる
├─ metro.py    東京メトロの路線・駅（変わらないデータなのでコードに持つ）
├─ feed.py     上流からの取得
├─ store.py    保存（購読・端末・履歴）
├─ service.py  取り込み→判定→配信をつなぐ中心
├─ notify.py   配信（画面へ即時／携帯のOS通知）
└─ api.py      HTTPの入口
web/           画面（PWA。組み立ての仕組みを使わない素のHTML/CSS/JS）
```

**Ver1との決定的な違い**：上流への問い合わせが利用者数と無関係。

| | Ver1 | Ver2 |
|---|---|---|
| 上流への問い合わせ | 利用者1人につき1本（1万人なら毎秒5,000回） | 路線ごとに1本（毎秒5回以下） |
| 利用者 | 1人だけ（設定がサーバー全体で1組） | 何人でも（購読は利用者ごと） |
| 再起動したとき | 同じ列車でまた鳴る | 鳴らない（期限つきの重複排除） |
| 通知の速さ | 駅に着いてから | **近づいた時点**（1駅ぶん早い） |
| 画面を閉じたとき | 鳴らない | OSのお知らせが届く |

## Ver1（旧版）を消すとき

Ver2をスマホで実際に確認し、問題がなければ次を削除できます。

```
app.py  monitor.py  static/  templates/  history.csv
```

あわせて `requirements.txt` の「Ver1」の3行（Flask・requests・gunicorn）も削除できます。
