# TOYOCHO ALERT Ver2 リリース前チェックリスト

- 作成日：2026-08-07
- 目的：商用リリース前に、端末ごとの確認と残作業を漏れなく潰す
- 前提：**すべての確認はHTTPS（`https://`）で行うこと**。
  サービスワーカーとお知らせ（Web Push）は、`localhost`以外では
  HTTPSでないと動かない決まりのため、httpのままでは何も確認できない。

---

## 0. 確認を始める前に（これが済まないと端末確認に入れない）

- [ ] HTTPSで公開されている（独自ドメイン or `*.fly.dev` などの証明書付き）
- [ ] Web Pushの鍵（VAPID）を生成し、`VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY` を設定した
- [ ] `/api/health` が `{"status":"ok"}` を返す
- [ ] `push_enabled` が `true` になっている（`/api/health`で確認）

---

## 1. iPhone（iOS Safari）

**もっとも制約が多い端末。ここが通れば他は概ね通る。**

### 導入
- [ ] iOS 16.4以降である（これ未満は**お知らせ機能が一切使えない**）
- [ ] Safariでサイトを開ける（Chrome等ではなくSafariで行うこと）
- [ ] 共有ボタン →「ホーム画面に追加」ができる
- [ ] **ホーム画面のアイコンから起動**した（※Safariのタブのままではお知らせを受け取れない）
- [ ] アイコン・アプリ名（メトロ通知）が正しく表示される
- [ ] 起動時にアドレスバーが出ない（全画面で表示される）
- [ ] ノッチ／ダイナミックアイランドに文字が隠れない（上下の余白が正しい）

### 通知（アプリを開いている状態）
- [ ] 「音とお知らせを許可する」を押すと、許可を求める表示が出る
- [ ] 列車が近づくと全画面のアラームが出る
- [ ] **音が鳴る**
- [ ] ⚠️ **本体の消音スイッチ（マナーモード）をオンにして確認**
      → iPhoneでは消音時に音が出ない可能性が高い。出ない場合は
      「マナーモードでは鳴りません」と画面で案内する必要がある
- [ ] ⚠️ **振動は動作しない**（iOS Safariは振動に非対応）。
      振動前提の案内文になっていないか確認する
- [ ] 「止める」を押すとアラームが消え、音が止まる
- [ ] アラーム表示中に画面が自動で暗くならない

### 通知（アプリを閉じている状態）
- [ ] アプリを閉じた（ホーム画面に戻した）状態でお知らせが届く
- [ ] 完全に終了させた（アプリスイッチャーから消した）状態でお知らせが届く
- [ ] 画面ロック中にお知らせが届く
- [ ] お知らせをタップするとアプリが開く
- [ ] 低電力モードでもお知らせが届く

### 継続利用
- [ ] 一度閉じて翌日開いても、見張りの設定が残っている
- [ ] **7日間使わなかった後**でも設定が残っている（iOSはデータを消すことがある）
- [ ] 機内モード→解除で、通知の受信が自動的に復帰する

## 2. Android（Chrome）

### 導入
- [ ] Chromeでサイトを開ける
- [ ] 「アプリをインストール」または「ホーム画面に追加」ができる
- [ ] インストール後、アイコンから全画面で起動する
- [ ] **ブラウザのタブのままでもお知らせが届く**（iPhoneとの違い）

### 通知
- [ ] 許可を求める表示が出て、許可できる
- [ ] アプリを開いている間、全画面アラーム＋音＋**振動**が動く
- [ ] アプリを閉じた状態でお知らせが届く
- [ ] **画面を消した状態で5分以上放置**してもお知らせが届く
      （届かない場合は端末の「電池の最適化」から本アプリを除外する案内が必要）
- [ ] お知らせが消えずに残る（自動で消えないこと）
- [ ] お知らせをタップするとアプリが開く
- [ ] マナーモード時の挙動を確認し、必要なら案内文を追加

### 継続利用
- [ ] データセーバーをオンにしても通知が届く
- [ ] Wi-Fi→モバイル回線の切り替えで、通知の受信が自動復帰する

## 7. リリース判定（2026-08-07 時点）

**総合 52点／100点 → 判定：まだ公開不可**

| 観点 | 重み | 点数 | 理由 |
|---|---|---|---|
| 中核機能の正しさ | 25% | 95 | 84件のテスト＋実データで検証済み。二重通知・複数利用者の分離を確認 |
| 保守性・設計 | 15% | 90 | 判定層が外部依存ゼロ。全10系統を上流と自動照合 |
| 通知の到達性 | 25% | 40 | 画面を開いている間（SSE）は実測0.5秒で確認済み。**画面を閉じている間のお知らせ（Web Push）は一度も動かしていない** |
| 端末対応（実機） | 15% | 20 | PWAの部品は揃っているが、**4端末とも確認ゼロ** |
| 運用（公開・監視・バックアップ） | 10% | 10 | 未着手。手元でしか動いていない |
| 商用要件（規約・データ許諾・引き継ぎ） | 10% | 10 | 未着手 |

**判定の理由**：コードの完成度は高いが、**リリース準備度がほぼゼロ**。
とくにHTTPSでの公開を一度も行っていないため、サービスワーカー・PWA導入・
Web Pushという「画面を閉じていても届く」部分が**一行も実行されていない**。
これは製品価値の半分にあたるため、動作未確認のまま公開はできない。
